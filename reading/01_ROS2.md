# 01 ROS 2：node、topic、rclpy 與 CLI 除錯

對應：官方練習 `demo/section2-1`、參考文獻 [6] [8]、v1 第一題、v2 大題一～三（所有 node）。

## 1. 最少要懂的觀念

| 名詞 | 一句話 | 在 2-1 練習裡 |
|---|---|---|
| **node** | 參與 ROS 通訊的一個執行單位，通常一支程式建立一個 | `/publisher`、`/processor` |
| **topic** | 有名字的資料通道，**名稱 + message type** 決定誰跟誰連得上 | `/number`、`/double` |
| **message type** | 訊息的欄位結構，例如 `std_msgs/msg/Int32` 只有一個 `int32 data` | `ros2 interface show` 查得到 |
| **publisher / subscriber** | 送資料 / 收資料的一端；一個 topic 可以有多個 publisher 與多個 subscriber | processor 同時是 `/number` 的 sub 與 `/double` 的 pub |
| **QoS depth** | `create_publisher(..., 10)` 的 10：佇列能暫存幾筆 | — |
| Service / Action | 請求-回應 / 長時間工作；2-1 只用 Topic | — |

關鍵直覺：

- topic 是**用名字配對**的。名字差一個字元（`/temperture/raw`），ROS 就當成另一個 topic，**程式不會報錯**，只是收不到東西。
- 型別也要一致。publisher 是 `Int32`、subscriber 是 `Float32` 的話，兩端不會連上。
- **topic 存在 ≠ 有資料在傳。** subscriber 還在時，即使 publisher 停了，`ros2 topic list` 仍看得到它（`Publisher count: 0`）。
- 多個 publisher 可以發到同一個 topic，subscriber 會收到**交錯**的訊息。

## 2. rclpy 骨架（背起來）

```python
import rclpy
from rclpy.node import Node
from std_msgs.msg import Int32, Float32

class Processor(Node):
    def __init__(self):
        super().__init__('processor')                                   # node 名稱
        self.sub = self.create_subscription(Int32, '/number', self.on_msg, 10)
        self.pub = self.create_publisher(Float32, '/half', 10)
        self.timer = self.create_timer(1.0, self.on_timer)              # 週期（秒）

    def on_msg(self, msg):          # 每收到一筆就被呼叫一次
        out = Float32()
        out.data = msg.data / 2.0   # Float32.data 一定要是 float
        self.pub.publish(out)

    def on_timer(self):
        self.get_logger().info('still alive')

def main():
    rclpy.init()
    node = Processor()
    try:
        rclpy.spin(node)            # 進入事件迴圈：等訊息、觸發 timer、呼叫 callback
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.try_shutdown()
```

### rclpy 容易踩的雷

| 雷 | 後果 | 正確做法 |
|---|---|---|
| `Float32.data = 3`（int） | `AssertionError`：欄位型別檢查 | `float(x)` 或 `x / 100.0` |
| `Int32.data = 2**31` | `AssertionError`：超出 int32 範圍（2-1 的 processor 收到很大的數乘 2 就會爆） | 先檢查範圍或換 `Int64` |
| publisher 宣告 `Int32`，卻 `publish(Float32())` | `TypeError` | 宣告與發布的型別一致 |
| 在 callback 裡 `time.sleep()` 或跑很久 | 預設的單執行緒 executor 會卡住，其他 callback 與 timer 全部延遲 | callback 要短；長工作放 timer 或另開執行緒 |
| 用 `//` 做平均 | 小數消失（`2701 // 3`） | `/` |
| 每次都發布狀態 | 下游（例如警報器）收到一堆重複事件 | 用狀態機，只在**狀態改變**時發布 |

> 預設的 `rclpy.spin()` 是單執行緒的：同一個 node 的 callback 不會同時執行，所以第一題不用鎖。這和第三題的多執行緒是不同的世界。

### 移動平均與遲滯（第一題的兩個小演算法）

```python
from collections import deque
window = deque(maxlen=5)          # 自動丟掉最舊的一筆
window.append(x)
avg = sum(window) / len(window)
```

遲滯（hysteresis）：開與關用**兩個不同的門檻**，中間是「維持原狀」的區間，避免數值在門檻附近抖動時狀態一直切換。

```text
          OFF ──(avg >= 30.0)──> ON
          ON  ──(avg <= 28.0)──> OFF
   28.0 < avg < 30.0：維持目前狀態，不發布
```

## 3. CLI 指令表

| 想知道 | 指令 | 你會看到 |
|---|---|---|
| 有哪些 node | `ros2 node list` | `/publisher` |
| node 收發哪些 topic | `ros2 node info /processor` | `Subscribers:` / `Publishers:` 與型別 |
| 有哪些 topic | `ros2 topic list`（`-t` 連型別一起列） | `/number` |
| topic 的型別與兩端數量 | `ros2 topic info /number`（`-v` 看 QoS） | `Publisher count: 1`、`Subscription count: 0` |
| 型別有哪些欄位 | `ros2 interface show std_msgs/msg/Int32` | `int32 data` |
| 實際資料 | `ros2 topic echo /number`（`--once` 只收一筆） | `data: 82` |
| 頻率 | `ros2 topic hz /number` | `average rate: 1.000` |
| 手動送資料 | `ros2 topic pub --once /number std_msgs/msg/Int32 "{data: 21}"` | 下游收到 |
| 持續送 | `ros2 topic pub --rate 5 /number std_msgs/msg/Int32 "{data: 1}"` | 5 Hz |

`echo` 等於暫時建一個 subscriber，`pub` 等於暫時建一個 publisher。**除錯時不用另外寫測試程式**，可以直接對某個 node 的輸入送已知資料、在輸出端 echo 看結果。

## 4. 除錯流程（官方 2-1 第 6 節，背起來）

```text
node 是否存在          ros2 node list
      ↓
topic 是否存在         ros2 topic list
      ↓
兩端是否連到同一個 topic  ros2 node info <兩端的 node>（比對名稱與型別）
      ↓
pub / sub 數量是否合理   ros2 topic info <topic>
      ↓
實際是否有資料          ros2 topic echo / hz
      ↓
單獨測某個 node          ros2 topic pub 已知輸入 → echo 輸出
```

**判讀範例**

| 觀察 | 推論 |
|---|---|
| `topic info /raw`：Pub 1 / Sub 0，但 monitor 在跑 | monitor 訂到別的名字（或型別不同）→ `node info /monitor` 確認 |
| `topic list` 裡同時有 `/temperature/raw` 和 `/temperture/raw` | 有人拼錯，兩個 topic 各只有一端 |
| `hz` 正常但 `echo` 的數值不對 | 傳輸沒問題，是 node 內的計算邏輯錯 |
| `echo /alarm` 沒輸出，但規格是「狀態改變才發布」 | 可能完全正常 |
| `node list` 看不到某個 node | 程式沒啟動、已崩潰，或 node 名稱和你以為的不一樣 |

## 5. 官方「想一想」參考答案

1. **processor 訂閱的名稱與 publisher 差一個字元，用哪些指令定位？**
   `ros2 node list`（兩個 node 都在）→ `ros2 topic list`（看到兩個長得很像的 topic）→ `ros2 node info /processor` 與 `ros2 node info /publisher`（各自連的名字不同）→ `ros2 topic info` 兩個 topic（各自只有 pub 或只有 sub）。
2. **兩個 publisher 同時發到 `/number`？**
   `Publisher count: 2`；processor 會收到兩邊**交錯**的資料，`/double` 的發布頻率約變成兩倍（`topic hz` 可驗證）。ROS 不會報錯，也不會只取其中一個。

## 7. 自我檢查

<details><summary>1. <code>ros2 topic info /x</code> 顯示 Publisher 0、Subscription 1，代表什麼？</summary>
有 node 在等 /x 的資料，但目前沒有任何 publisher。topic 仍然「存在」。可以用 <code>ros2 topic pub</code> 補一筆測試資料。
</details>

<details><summary>2. 為什麼 <code>out.data = sum(w) // len(w) / 100</code> 會錯？</summary>
<code>//</code> 先做整數除法，小數被截掉後才除以 100。例如 (2500+2600+2701)/3 = 2600.33，用 <code>//</code> 會變成 26.00 而不是 26.0033。
</details>

<details><summary>3. callback 裡呼叫 <code>time.sleep(2)</code>，<code>topic hz</code> 會看到什麼？</summary>
該 node 的輸出頻率掉到約 0.5 Hz；同一個 node 的其他 callback 與 timer 也會延遲（單執行緒 executor）。QoS 佇列滿了以後，舊訊息會被丟掉。
</details>

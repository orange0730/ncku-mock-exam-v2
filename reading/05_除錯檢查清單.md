# 05 除錯檢查清單：不靠 AI，自己把錯找出來

這份清單的每一條，都來自這份模擬考裡真的出現過的錯誤。目標是讓你在考場上有一套**固定的步驟**，不用靠靈感。

---

## 1. 固定流程（每一個沒拿到分的項目都照走）

```text
① 讀評分訊息 → ② 分類（是哪一種錯？見第 2 節）→ ③ 提出一個假設
→ ④ 做最小的實驗驗證假設 → ⑤ 只改一個地方 → ⑥ 本機跑評分 → ⑦ commit（訊息寫改了什麼）
```

- **一次只改一個地方。** 一次改三處，分數動了你不知道是哪一處的功勞，分數沒動你也不知道哪一處白改了。
- **本機先跑過再 commit。** `python3 q1_ebnn/grade.py` 幾秒就有結果，考場上的 CI 要排隊。
- **commit 訊息寫改了什麼：** `Q1: hidden 改用 XNOR`，不要寫 `Q1: fix all`。分數掉下來時，`git log` 才看得出是哪一步。
- **設時間上限。** 同一個錯卡 15 分鐘就先跳去拿別的分數，或用 `--hint 1`（見第 6 節）。

---

## 2. 讀懂評分訊息

| 訊息長這樣 | 代表 | 先往哪裡找 |
|---|---|---|
| `期望 0x80000001，實際 0x00000000` | 數值錯 | 把兩個數寫成二進位對齊比較（第 4 節的指令） |
| `期望 … 實際 …` 只差在大小寫、補零、正負號 | 輸出格式錯 | 規格的格式字串、`%08x` / `:08x` |
| `程式當掉了（exit code -11，SIGSEGV…）` | 讀寫了不該碰的記憶體 | 陣列越界、`n - 1` 在 `n = 0` 時變極大、指標沒初始化 |
| `程式當掉了（exit code -6，SIGABRT…）`、`引擎中止：…` | 程式自己中止 | 訊息裡寫了違反哪條規則（對齊、count 是 0、沒 claim …） |
| `超過 60 秒沒有結束` | 無窮迴圈或演算法太慢 | 迴圈條件、O(n²)、無號數倒數 `for (i = n - 1; i >= 0; i--)` |
| `callback 拋出 AssertionError: The 'data' field must be …` | ROS 訊息欄位型別錯 | `Int32` 放了 float、`MultiArray.data` 放了 ctypes 陣列 |
| `發布了 0 個…`、`實際 []` | 根本沒收到 / 沒發出 | topic 名稱、型別（兩端型別不同就連不上）、callback 有沒有被呼叫 |
| `TabError` / `IndentationError` / `無法載入` | Python 語法 | 先跑 `python3 -m py_compile 檔名.py` |
| `組譯失敗：line N …` | PIO 語法 | 那一行的指令格式 |
| 某一項分數一直 0，但你明明改了 | 這一項要好幾個條件**同時**對 | 讀評分表的項目名稱，例如「XNOR、門檻、位元位置」= 三件事 |

## 3. 檢查清單：每個函式從頭掃一遍

### C：迴圈與陣列

- [ ] 迴圈跑幾次？從 0 開始的話是 `< N` 還是 `<= N`？
- [ ] 陣列有幾格？最後一個合法 index 是 `N - 1`。
- [ ] `size_t` 是**無號**的：`n - 1` 在 `n = 0` 時是極大的數；`i >= 0` 永遠成立。
- [ ] 讀 `req[1]`、`p[i]` 之前，確定長度夠了嗎？（先檢查、再讀）
- [ ] 函式最後有沒有 `return`？每條路徑都有嗎？

### C：位元

- [ ] 要的是 XOR（不同）還是 XNOR `~(a ^ b)`（相同）？
- [ ] 位元位置：bit `j` 還是 bit `31 - j`？規格怎麼說？下游怎麼用？
- [ ] 欄位的 mask 寬度：8 位元欄位要 `& 0xFF`，不是 `& 0x0F`。
- [ ] 移位量：`1u << 32`、`x >> 32` 是未定義行為；寬度可能是 32 時要特判。
- [ ] 常數用 `1u`、`0xFFu`，不要用有號的 `1`（`1 << 31` 是溢位）。
- [ ] 運算子優先順序：`x & mask == 0` 其實是 `x & (mask == 0)`。不確定就加括號。

### C：型別與位元組順序

- [ ] byte 用 `uint8_t`，不要用 `char`（有沒有號依平台而定）。
- [ ] 小的型別移位前先轉成 `uint32_t`：`(uint32_t)p[0] << 24`。
- [ ] 64 位元拆兩個 32 位元：哪一個是低位？`img[0]` 還是 `img[1]`？
- [ ] big-endian（SHA 的長度、網路封包）還是 little-endian（job id、x86 / ARM 的記憶體）？

### 單位與規格

- [ ] bytes 還是筆數（DMA 的 count 是筆數）？°C 還是 0.01 °C？位元數還是 bytes（SHA 的長度是位元數）？
- [ ] 比較是 `>` 還是 `>=`？同分時選第一個還是最後一個？
- [ ] 邊界：0、1、全 1、最大值、剛好等於門檻、55 / 56 / 64 bytes、`count = 32`。

### 順序與收尾

- [ ] 先檢查、再使用（長度、範圍、claim 是否成功）。
- [ ] 規格要求的發布順序（先 scores 再 prediction）、依序號發布。
- [ ] 用完要還：release 通道、disable sniffer、free 記憶體。

### PIO

- [ ] `jmp x--`：**先**看 X 是否非 0 決定跳不跳，**然後**一律減 1。
- [ ] 計數從 `0xFFFFFFFF`（`mov x, ~null`）往下數，最後 `mov isr, ~x`。
- [ ] `jmp !y` 是「y 為 0 時跳」。極性搞反就數反了。
- [ ] 每個輸入剛好 `pull` 一次、輸出幾個 word 就 `push` 幾次。
- [ ] 用 `python3 ../common/pio_sim.py 程式.pio 0x5 --trace` 一步一步看暫存器。

### ROS 2 node

- [ ] node 名稱、topic 名稱逐字對照規格（單複數、斜線）。
- [ ] 訂閱與發布的訊息型別逐一對照規格表，不要用猜的。
- [ ] `Int32.data` 要 int、`Float32.data` 要 float、`MultiArray.data` 要 list。
- [ ] Python 縮排：全部用空白，不要混 tab。

### 封包與分散式（大題二、三）

- [ ] header 每個欄位的位置與寬度（`seq << 16 | first << 8 | count`）。
- [ ] 回應用序號 / job id 對帳，不要假設回應依序到達。
- [ ] 每份工作是不是剛好分配一次？有沒有漏、有沒有重複？
- [ ] 送出去就別等（pipeline）；結果依原始順序發布。

### 演算法規格（SHA-0、CRC-32）

- [ ] 先用公開的測試向量驗證：`SHA-0("abc") = 0164b8a9…`、`CRC32("123456789") = cbf43926`。
- [ ] `python3 common/algos_ref.py` 就是 Python 的參考實作，可以拿來比對中間值。

## 4. 自己做實驗的工具

**看二進位（比對期望與實際）：**

```bash
python3 -c "for v in (0x80000001, 0x00000001): print(f'{v:032b}')"
```

**寫一個 10 行的小測試，配 AddressSanitizer 編譯。** 陣列越界、`1u << 32` 這類錯誤會被直接指出是哪一行：

```bash
cat > /tmp/try_bnn.c <<'EOF'
#include <stdio.h>
#include "bnn.h"
int main(void) {
    uint32_t img[2] = {0x5262423Cu, 0x3C42464Au};     /* 數字 0 的模板 */
    int32_t scores[10];
    int pred = bnn_infer(img, scores);
    printf("pred = %d, hidden = 0x%08X\n", pred, bnn_hidden(img));
    for (int k = 0; k < 10; k++) printf("%d ", scores[k]);
    printf("\n");
    return 0;
}
EOF
gcc -g -Wall -Wextra -fsanitize=address,undefined -Icommon -Iq1_ebnn q1_ebnn/bnn.c /tmp/try_bnn.c -o /tmp/try_bnn && /tmp/try_bnn
```

越界時 ASan 會印出 `stack-buffer-overflow`，並指出是 `bnn.c` 的哪一行。其他題同樣做法：`#include` 那一題的 `.h`，換掉要測的函式。

**直接從 Python 呼叫你的 C 函式（不用寫 main）：**

```bash
python3 -c "
import sys, ctypes; sys.path.insert(0, 'common')
from clib import build_and_load
lib, _ = build_and_load('try', ['q3_algos/algos.c', 'q3_algos/engine.c', 'q3_algos/bench.c'], include_dirs=['q3_algos'])
lib.crc32_sw.restype = ctypes.c_uint32
print(hex(lib.crc32_sw(b'123456789', 9)))   # 應該是 0xcbf43926
"
```

**ROS node：**不用 ROS 也能測。評分程式就是用 `common/fake_ros` 跑的，看它的訊息即可。真的 ROS 環境用 `ros2 node info`、`ros2 topic info`、`ros2 topic echo`（見 01）。

## 5. 考場時間分配

1. **前 5 分鐘：** 讀三題的評分表，標出「便宜的分數」（例如格式、邊界、明顯的差一）。
2. **每個錯最多 15 分鐘**，超過就先跳下一個，最後再回來。
3. **正確性優先於效率。** 效率分數都要正確性全過才給。
4. **每拿到一點分就 commit。** 最後 10 分鐘不要再大改，確認 CI 上的分數就是你要交的版本。

---

## 6. 卡住時：分級提示（取代問 AI）

```bash
python3 q1_ebnn/grade.py --hint                     # 第 1 級：是哪一類錯
python3 q1_ebnn/grade.py --hint 2                   # 第 2 級：在哪裡
python3 q1_ebnn/grade.py --hint 3 --item bnn_hidden # 第 3 級：怎麼改（只看某一項）
```

建議用法：先只要第 1 級，配合本清單自己找 10 分鐘；還是卡住才要第 2 級；第 3 級是最後手段。每次查看都會記錄下來，CI 的輸出會顯示累計次數。練習的目標是**這個數字一輪比一輪少**。

```text
日期   題目 / 函式      症狀（評分訊息）                     原因類別   我怎麼找到的

```

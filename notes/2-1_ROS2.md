## 2. ROS 2 基本概念

| 名詞 | 說明 |
|---|---|
| ROS 2 | Robot Operating System 2，開發機器人軟體的開源框架（函式庫 + 工具） |
| **node** | 執行特定功能並參與 ROS 通訊的單位。一支程式通常建立一個 node。名稱以 `/` 開頭顯示（`/publisher`） |
| **topic** | node 之間傳資料的通道（bus）。有**名稱**與**固定的 message type** |
| **message type** | 訊息結構，例如 `std_msgs/msg/Int32` = 套件 `std_msgs` 裡的 msg `Int32`，只有一個欄位 `int32 data` |
| publisher / subscriber | 發布資料的一方 / 接收資料的一方 |
| QoS depth | `create_publisher(..., 10)` 的 10：佇列長度（queue size），subscriber 來不及收時最多暫存幾筆 |

**三種通訊方式**（2-1 只用 Topic）：

| 方式 | 用途 | 例子 |
|---|---|---|
| **Topic** | 持續、非同步地傳送資料 | 感測器持續發布量測值 |
| Service | 一次 request / response | 查詢或修改某項設定 |
| Action | 需要一段時間才完成的工作，可回報進度或取消 | 要求機器人移動到指定位置 |

**關鍵事實**

- 一個 node 可以發布任意多個 topic，也可以同時訂閱任意多個 topic（processor 同時是 `/number` 的 subscriber 與 `/double` 的 publisher）。
- topic 可以一對一、一對多、多對一、多對多。
- **publisher 與 subscriber 必須用同一個 message type 才能溝通**；topic **名稱差一個字元就是另一個 topic**，程式不一定會報錯。
- **topic 存在 ≠ 有資料在傳**：只要還有一端（例如 subscriber）在，topic 就會出現在 `ros2 topic list`。
- 建立 node 的程式停止後，該 node 會從系統中消失。
- `/parameter_events`、`/rosout` 是 ROS 2 系統本身的 topic，與練習無關，可忽略。
- `ros2 topic echo` 會暫時建立一個 subscriber node（名稱像 `/_ros2cli_26646`），`ros2 topic pub` 會暫時建立一個 publisher node。

## 3. CLI 完整速查

> 每開一個新終端機都要先 `source /opt/ros/jazzy/setup.bash`（官方 Docker 映像已寫進 `.bashrc`，`docker exec` 進去也會自動 source）。

### 3.1 node

| 指令 | 作用 | 輸出範例 |
|---|---|---|
| `ros2 node list` | 列出正在執行的 node | `/processor`<br>`/publisher` |
| `ros2 node info <node>` | 該 node 的 Subscribers / Publishers（還有 services、actions） | 見下方 |

```text
$ ros2 node info /processor
/processor
  Subscribers:
    /number: std_msgs/msg/Int32
  Publishers:
    /double: std_msgs/msg/Int32
    /parameter_events: rcl_interfaces/msg/ParameterEvent
    /rosout: rcl_interfaces/msg/Log
```

### 3.2 topic

| 指令 | 作用 |
|---|---|
| `ros2 topic list` | 列出所有 topic |
| `ros2 topic list -t` | 同上，並在後面用 `[ ]` 附上型別，例如 `/turtle1/cmd_vel [geometry_msgs/msg/Twist]` |
| `ros2 topic info <topic>` | 型別、`Publisher count`、`Subscription count` |
| `ros2 topic info <topic> --verbose`（或 `-v`） | 再列出每個端點的 node 名稱、namespace、型別、type hash、endpoint type、GID、**QoS profile** |
| `ros2 topic echo <topic>` | 持續印出收到的訊息，每筆以 `---` 分隔；`Ctrl-C` 停止 |
| `ros2 topic hz <topic>` | 發布頻率：`average rate`、`min`、`max`、`std dev`、`window` |
| `ros2 topic bw <topic>` | 頻寬：`1.51 KB/s from 62 messages`、訊息大小 mean / min / max |
| `ros2 topic find <type>` | 找出使用某型別的所有 topic |
| `ros2 topic pub <topic> <type> '<args>'` | 由 CLI 發布訊息（YAML 格式） |
| `ros2 interface show <type>` | 顯示訊息型別的欄位 |
| `ros2 run rqt_graph rqt_graph` | 圖形化顯示 node 與 topic 的連線（或 rqt → Plugins → Introspection → Node Graph） |

`topic info` 範例：

```text
$ ros2 topic info /number
Type: std_msgs/msg/Int32
Publisher count: 1
Subscription count: 0
```

`topic info -v` 會多出（每個端點一段）：

```text
Node name: teleop_turtle
Node namespace: /
Topic type: geometry_msgs/msg/Twist
Topic type hash: RIHS01_...
Endpoint type: PUBLISHER
GID: 24.ba.3e....
QoS profile:
  Reliability: RELIABLE
  History (Depth): KEEP_LAST (7)
  Durability: VOLATILE
  Lifespan: Infinite
  Deadline: Infinite
  Liveliness: AUTOMATIC
  Liveliness lease duration: Infinite
```

> `hz` 與 `bw` 量的是**它們自己那個 subscriber 的接收速率**，受平台資源與 QoS 影響，不一定剛好等於 publisher 的速率。

### 3.3 `ros2 topic pub` 詳解

```bash
ros2 topic pub --once /number std_msgs/msg/Int32 "{data: 21}"            # 發一筆就結束
ros2 topic pub --once -w 2 /turtle1/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 2.0}, angular: {z: 1.8}}"
ros2 topic pub --rate 5 /number std_msgs/msg/Int32 "{data: 7}"           # 每秒 5 筆，持續發布
ros2 topic pub /turtle1/cmd_vel geometry_msgs/msg/Twist                    # 不給資料：預設值、1 Hz
```

| 選項 | 意思 |
|---|---|
| `--once`（`-1`） | 發一筆就結束 |
| `-w N`（`--wait-matching-subscriptions N`） | 等到至少 N 個 subscriber 連上才發。用 `--once` 時常需要，否則可能在 subscriber 連上前就發完 |
| `--rate R`（`-r`） | 每秒 R 筆（預設 1） |
| `--times N`（`-t`） | 發 N 筆後結束 |
| `--print N`（`-p`） | 每 N 筆印一次 |
| `--qos-depth`、`--qos-reliability`、`--qos-durability`、`--qos-history`、`--qos-profile` | QoS 設定 |
| `--node-name`（`-n`）、`--keep-alive`、`--yaml-file`、`--stdin`、`--use-sim-time` | 其他 |

**YAML 參數規則**

- 整個參數用引號包起來：`"{data: 21}"`。
- 巢狀欄位用 `{}`：`"{linear: {x: 2.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 1.8}}"`。
- 只給要改的欄位即可，其餘是預設值：`"{linear: {x: 2.0}, angular: {z: 1.8}}"`。
- 陣列：`"{data: [1, 2, 3]}"`（例如 `std_msgs/msg/Int32MultiArray`）。
- 有 `std_msgs/msg/Header` 的訊息可寫 `header: "auto"` 自動填時間；`builtin_interfaces/msg/Time` 欄位可寫 `"now"`。
- 輸入 `ros2 topic pub <topic> <type> \'<TAB>` 可以自動補出整個訊息的 YAML 樣板（Windows 不支援）。

發布時終端機會顯示：

```text
publisher: beginning loop
publishing #1: std_msgs.msg.Int32(data=21)
```

| 步驟 | 在哪裡 | 指令 | 預期結果 / 重點 |
|---|---|---|---|
| 0 | 任一 | `cd section2-1` | — |
| 2 | A | `ros2 node list`、`ros2 topic list` | 沒有練習的 node；可能看到 `/parameter_events`、`/rosout`，也可能沒輸出 |
| 3 | A | `python3 publisher.py` | `publisher 已啟動，按 Ctrl-C 停止` |
| 3.1 | B | `ros2 node list` | `/publisher` |
| 3.2 | B | `ros2 topic list` | 多了 `/number` |
| 3.3 | B | `ros2 node info /publisher` | Publishers 裡有 `/number: std_msgs/msg/Int32` |
| 3.4 | B | `ros2 topic info /number` | `Publisher count: 1`、`Subscription count: 0` |
| 3.5 | B | `ros2 interface show std_msgs/msg/Int32` | `int32 data` |
| 3.6 | B | `ros2 topic echo /number`、`ros2 topic hz /number` | `data: 82` `---` …；`average rate: 1.000` |
| 3.7 | A→B | A 按 `Ctrl-C`，B 再 `ros2 node list` | `/publisher` 消失 |
| 4 | A、B | A：`python3 publisher.py`；B：`python3 processor.py` | B 印出 `received: 51` … |
| 4.1 | C | `ros2 node list`、`ros2 topic list` | 多了 `/processor` 與 `/double` |
| 4.2 | C | `ros2 node info /processor` | Subscribers `/number`；Publishers `/double` |
| 4.3 | C | `ros2 topic info /number` | `Subscription count` 從 0 變 1 |
| 4.4 | C | `ros2 topic echo /double`（保持執行） | 持續看到 2 倍的值 |
| 5 | A | 停掉 publisher，`ros2 topic info /number` | `Publisher count: 0`、`Subscription count: 1` |
| 5 | A | `ros2 topic pub --once /number std_msgs/msg/Int32 "{data: 21}"` | C 收到 `data: 42`；`-5` → `-10`；`0` → `0`；`100` → `200` |
| 7 | 全部 | `Ctrl-C`；`docker exec` 的終端機 `exit`；最後第一個 shell `exit` | container 停止並刪除。先離開第一個 shell，其他終端機會跟著中斷（正常） |

選讀：`processor.py` 裡 `INPUT_TOPIC = '/number'` 對應 subscriber；`Int32` 對應 `std_msgs/msg/Int32`；`received.data` 對應 `int32 data`。

## 5. rclpy 程式範例

### 5.1 官方 demo 原始碼（publisher.py、processor.py 重點）

```python
# publisher.py：每秒發佈一個 1～100 的隨機整數
class Publisher(Node):
    def __init__(self):
        super().__init__('publisher')                          # node 名稱 → /publisher
        self.pub = self.create_publisher(Int32, '/number', 10) # 型別、topic、QoS depth
        self.timer = self.create_timer(1.0, self.tick)         # 每 1.0 秒呼叫 tick

    def tick(self):
        msg = Int32()
        msg.data = random.randint(1, 100)
        self.pub.publish(msg)

# processor.py：收到 /number，乘以 2 後發到 /double
class Processor(Node):
    def __init__(self):
        super().__init__('processor')
        self.sub = self.create_subscription(Int32, '/number', self.on_msg, 10)
        self.pub = self.create_publisher(Int32, '/double', 10)

    def on_msg(self, received):
        print(f'received: {received.data}', flush=True)
        out = Int32()
        out.data = received.data * 2
        self.pub.publish(out)

def main():
    rclpy.init()
    node = Processor()
    try:
        rclpy.spin(node)               # 事件迴圈：等訊息、觸發 timer、呼叫 callback
    except KeyboardInterrupt:          # Ctrl-C
        pass
    finally:
        node.destroy_node()
        rclpy.try_shutdown()
```

### 5.2 完整範本：訂閱 → 處理 → 發布（可直接改來用）

```python
# file: template_node.py
"""範本：訂閱一個 topic，處理後發布到另一個 topic，另有一個定時器。"""
import rclpy
from rclpy.node import Node
from std_msgs.msg import Int32, String


class Worker(Node):
    def __init__(self):
        super().__init__('worker')                                   # node 名稱
        self.sub = self.create_subscription(Int32, '/input', self.on_input, 10)
        self.pub = self.create_publisher(Int32, '/output', 10)
        self.stat_pub = self.create_publisher(String, '/stats', 10)
        self.timer = self.create_timer(1.0, self.on_timer)           # 每 1 秒
        self.count = 0

    def on_input(self, msg):              # 每收到一筆呼叫一次
        self.count += 1
        out = Int32()
        out.data = msg.data * 2           # Int32 要 int；Float32 要 float
        self.pub.publish(out)
        self.get_logger().info(f'in={msg.data} out={out.data}')

    def on_timer(self):
        s = String()
        s.data = f'count={self.count}'
        self.stat_pub.publish(s)


def main(args=None):
    rclpy.init(args=args)
    node = Worker()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.try_shutdown()


if __name__ == '__main__':
    main()
```

測試它（三個終端機）：

```bash
python3 template_node.py
ros2 topic echo /output
ros2 topic pub --once -w 1 /input std_msgs/msg/Int32 "{data: 21}"     # /output 應收到 42
```

### 5.3 官方教學的 minimal publisher / subscriber（String）

```python
# file: minimal_pubsub.py
import rclpy
from rclpy.node import Node
from std_msgs.msg import String


class MinimalPublisher(Node):
    def __init__(self):
        super().__init__('minimal_publisher')
        self.publisher_ = self.create_publisher(String, 'topic', 10)    # 相對名稱 → /topic
        self.timer = self.create_timer(0.5, self.timer_callback)        # 0.5 秒
        self.i = 0

    def timer_callback(self):
        msg = String()
        msg.data = 'Hello World: %d' % self.i
        self.publisher_.publish(msg)
        self.get_logger().info('Publishing: "%s"' % msg.data)
        self.i += 1


class MinimalSubscriber(Node):
    def __init__(self):
        super().__init__('minimal_subscriber')
        self.subscription = self.create_subscription(String, 'topic', self.listener_callback, 10)

    def listener_callback(self, msg):
        self.get_logger().info('I heard: "%s"' % msg.data)


def main(args=None):
    rclpy.init(args=args)
    pub, sub = MinimalPublisher(), MinimalSubscriber()
    from rclpy.executors import SingleThreadedExecutor
    ex = SingleThreadedExecutor()      # 一個 process 跑兩個 node 要用 executor
    ex.add_node(pub)
    ex.add_node(sub)
    try:
        ex.spin()
    except KeyboardInterrupt:
        pass
    finally:
        pub.destroy_node()
        sub.destroy_node()
        rclpy.try_shutdown()


if __name__ == '__main__':
    main()
```

### 5.4 常用小技巧

```python
# 陣列訊息
from std_msgs.msg import Int32MultiArray
m = Int32MultiArray()
m.data = [int(v) for v in values]       # 一定要是 list / tuple / array.array 的 int

# 64-bit 拆兩個 32-bit
lo = value & 0xFFFFFFFF
hi = (value >> 32) & 0xFFFFFFFF

# 只觸發一次的 timer（延遲 delay 秒後做一件事）
def call_later(node, delay, fn):
    holder = {}
    def fire():
        holder['t'].cancel()
        fn()
    holder['t'] = node.create_timer(delay, fire)

# 現在時間（秒）
now = node.get_clock().now().nanoseconds / 1e9

# 一個 node 訂閱多個相似的 topic，callback 帶參數
for i in range(2):
    node.create_subscription(Int32, f'/board{i}/response', lambda msg, i=i: node.on_resp(i, msg), 10)
#          注意 lambda 的 i=i：不寫的話所有 callback 都會拿到最後一個 i

# 依序號排隊後依序發布
ready, next_out = {}, 0
def on_done(seq, value):
    global next_out
    ready[seq] = value
    while next_out in ready:
        publish(ready.pop(next_out))
        next_out += 1
```

- `rclpy.spin()` 預設是單執行緒：**同一個 node 的 callback 不會同時執行**，不用鎖；但 callback 裡不要 `sleep` 或做很久，會卡住其他 callback 與 timer。
- `get_logger().info / warn / error` 會輸出到終端機與 `/rosout`。

## 6. 訊息型別與欄位規則

| 型別 | 欄位 | Python 值的規則（違反會 AssertionError） |
|---|---|---|
| `std_msgs/msg/Int32` | `int32 data` | int，範圍 −2³¹ … 2³¹−1 |
| `std_msgs/msg/UInt32`、`UInt64`、`Int64`、`UInt8`… | `data` | int，對應範圍 |
| `std_msgs/msg/Float32`、`Float64` | `data` | **float**（`3` 不行，要 `3.0` 或 `float(x)`） |
| `std_msgs/msg/Bool` | `data` | bool |
| `std_msgs/msg/String` | `data` | str |
| `std_msgs/msg/Int32MultiArray` 等 | `layout`、`data[]` | `data` 是 int 序列（list/tuple/array.array；ctypes 陣列、numpy 物件要先轉） |
| `geometry_msgs/msg/Twist` | `Vector3 linear`、`Vector3 angular`（各 `float64 x,y,z`） | 巢狀：`msg.linear.x = 2.0` |

- `publish()` 的訊息型別必須和 `create_publisher` 宣告的相同，否則 `TypeError`。
- 型別名稱格式：`<package>/msg/<Name>`；Python import：`from std_msgs.msg import Int32`。
- 查欄位：`ros2 interface show std_msgs/msg/Int32MultiArray`。

## 8. 除錯流程與判讀表

官方建議的順序：

```text
node 是否存在            ros2 node list
      ↓
topic 是否存在           ros2 topic list
      ↓
兩端是否連到同一個 topic   ros2 node info <兩端的 node>（比對名稱與型別）
      ↓
pub / sub 數量是否合理     ros2 topic info <topic>
      ↓
實際是否有資料           ros2 topic echo / hz
      ↓
單獨測某個 node           ros2 topic pub 送已知輸入 → echo 看輸出
```

| 想確認的事 | 指令 |
|---|---|
| 預期的 node 是否正在執行？ | `ros2 node list` |
| 預期的 topic 是否存在？ | `ros2 topic list` |
| node 實際訂閱與發布了哪些 topic？ | `ros2 node info <node>` |
| topic 的型別，以及 pub / sub 數量是否正確？ | `ros2 topic info <topic>` |
| topic 上是否真的有資料？ | `ros2 topic echo <topic>` |
| topic 的發布頻率是否正常？ | `ros2 topic hz <topic>` |
| 想單獨測試某個 node 的輸入 | `ros2 topic pub` 發送已知資料，再用 `echo` 觀察輸出 |

**判讀**

| 觀察 | 推論 |
|---|---|
| Pub 1 / Sub 0，但另一端的 node 在跑 | 那個 node 訂到別的名字（拼錯）或型別不同 → `node info` 確認 |
| `topic list` 有兩個長得很像的 topic | 有人拼錯，兩個 topic 各只有一端 |
| `topic info` 顯示兩個型別（`-t` 或 `-v`） | 兩端型別不同，不會連上 |
| Pub 0 / Sub 1 | 有人在等，但沒有人發；可以手動 `pub` 測試 |
| `hz` 正常但 `echo` 數值錯 | 傳輸沒問題，是 node 內的計算錯 |
| `echo` 完全沒東西 | 沒有 publisher、名稱或型別不對，或 publisher 只在特定條件下才發（例如「狀態改變才發布」） |
| `node list` 看不到 | 程式沒啟動、已當掉，或 node 名稱跟你以為的不同 |
| `hz` 比預期低 | callback 太慢、QoS 佇列滿、有東西被丟掉 |

## 9. 常見錯誤

| 錯誤 | 結果 | 修正 |
|---|---|---|
| topic 拼錯（`/numbr`） | 收不到，不報錯 | 逐字對照；`topic list` |
| 型別不同（一端 Int32、一端 Float32） | 不會連上 | 對照 `node info` |
| `Float32.data = 3` | AssertionError | `float(3)` |
| `Int32.data` 超出範圍（例如 2³¹） | AssertionError | 先檢查或換大型別 |
| `publish()` 的型別和 publisher 不同 | TypeError | 一致 |
| `msg.data = ctypes 陣列 / numpy` | AssertionError（不是序列） | `[int(v) for v in arr]` |
| callback 裡 `time.sleep` | 其他 callback / timer 全部延遲 | 用 timer 或另開執行緒 |
| 忘了 `rclpy.init()` 或 `spin()` | node 建不起來 / callback 不會被呼叫 | 照範本 |
| 新終端機沒 source | `ros2: command not found` | `source /opt/ros/jazzy/setup.bash` |
| 用 `--once` 發，subscriber 沒收到 | 發得太早 | 加 `-w 1` |
| Python 縮排混 tab 與空白 | `TabError` | 全用空白 |

## 10. 「想一想」參考答案

1. **processor 訂閱的名稱與 publisher 差一個字元，用哪些指令定位？**
   `ros2 node list`（兩個 node 都在）→ `ros2 topic list`（出現兩個相似的 topic）→ `ros2 node info /processor` 與 `ros2 node info /publisher`（各自連的名字不同）→ `ros2 topic info` 兩個 topic（各自只有 pub 或只有 sub，另一邊是 0）。
2. **兩個 publisher 同時發到 `/number`？**
   `ros2 topic info /number` 顯示 `Publisher count: 2`；processor 收到兩邊**交錯**的資料，`/double` 的頻率約變兩倍（可用 `ros2 topic hz` 驗證）。ROS 不會報錯，也不會只取其中一個。

## 12. 多片開發板與 micro-ROS

去年考題用 ESP32 跑 ROS 2。微控制器上的 ROS 2 是 **micro-ROS**：板子上用 C 的 `rclc` API 建 node / publisher / subscriber，透過 UART、USB 或 UDP 連到電腦上的 **micro-ROS agent**，agent 再把它們接進 ROS 2 網路。

```text
[MCU：rclc node] ──序列埠 / Wi-Fi──> [micro-ROS agent] ──DDS──> ROS 2（你的 Python node、ros2 CLI）
```

- 從 `ros2 node list` 看，每片板子就是一個 node；除錯方式和本章完全相同。
- 多板分工的模式：協調者 node 對各板的 request topic 發布工作 → 各板在 response topic 回覆 → 協調者用**序號**對帳、依序發布結果。不要送一張等一張（pipeline），依板子速度分配工作。

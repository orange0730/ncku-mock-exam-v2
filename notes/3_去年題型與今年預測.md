## 1. 總覽：去年 → 今年

| 去年 | 核心技術 | 今年練習給的線索 | 今年可能的變化 |
|---|---|---|---|
| ROS 2 跑 eBNN | XNOR + popcount、位元打包、門檻、argmax | 2-2：位元運算、PIO（只有遞減的計數）、RISC-V | 板子換成 **RP2350**；popcount 交給 **PIO** 或 Hazard3 的 `cpop` / `xnor`；用 PIO 解析感測器位元流再推論 |
| 兩片板子平行跑 | 切工作、序號、合併、負載平衡、pipeline | 2-3：「兩個工作者、一個共享變數」、鎖要短 | 用 RP2350 的**雙核心**平行（共享結果要上鎖）；或兩片板子 + 協調者；量加速比 |
| 三片板子跑排序 / SHA-0 / CRC32 | 演算法正確性、位元組順序、分工 | 2-3：搬運引擎、PDF 寫「資料搬運／**校驗**周邊」 | **CRC32 用 DMA sniffer**；**SHA-256 用硬體加速器**；排序比效率；DMA 搬資料（count 是筆數！） |
| GitLab CI 評分 | commit 訊息題號 | — | 大概不變 |

**準備重點（依重要性）**

1. 位元運算寫對（XNOR、popcount、欄位、位元組順序、移位 UB）。
2. ROS 2 node 會寫、會用 CLI 除錯（topic 名稱與型別）。
3. 把工作切給多片板子 / 多個核心，用序號對帳、依序輸出，不送一張等一張。
4. DMA 的四拍節奏與 count 單位；sniffer 算 CRC；硬體 SHA-256。
5. PIO：OSR / ISR / X / Y、`jmp x--`、`mov ::`、autopull / autopush。

## 2. 共通架構：板子怎麼接上 ROS 2

```text
            ┌─────────────── 電腦（ROS 2 Jazzy）───────────────┐
板子 ─USB─> │ micro-ROS agent ──DDS──> 你的 Python 協調者 node   │
(rclc node) │                          ros2 CLI（node list / topic echo / pub） │
            └──────────────────────────────────────────────┘
```

- **micro-ROS**：在微控制器上跑的 ROS 2。板子上用 C 的 **rclc** API 建立 node / publisher / subscriber，透過 UART / USB 序列埠或 Wi-Fi（UDP）連到電腦上的 **micro-ROS agent**，agent 再把它們接進 ROS 2。
- 從電腦看，**每片板子就是一個 node**（`ros2 node list` 看得到），用一般的 topic 跟它溝通。
- 考場很可能已提供韌體範本與 agent 指令，你只要填演算法與 callback。**先找 repository 裡的 README 與範本。**

### 2.1 啟動 agent

```bash
# 序列埠（板子插 USB；ESP32 常見 /dev/ttyUSB0，RP2350 / Pico 常見 /dev/ttyACM0）
ros2 run micro_ros_agent micro_ros_agent serial --dev /dev/ttyUSB0 -b 115200
# 或用 Docker
docker run -it --rm -v /dev:/dev --privileged --net=host microros/micro-ros-agent:jazzy serial --dev /dev/ttyUSB0 -v6
# Wi-Fi（UDP）
ros2 run micro_ros_agent micro_ros_agent udp4 --port 8888
```

確認：`ros2 node list` 出現板子的 node；`ros2 topic list` 出現它的 topic。看不到時：插拔板子、按 reset（板子通常在開機時才連 agent）、確認序列埠名稱（`ls /dev/tty*`）、確認權限（`sudo usermod -aG dialout $USER`）、`-v6` 看 agent 日誌。

### 2.2 板子韌體骨架（rclc，ESP32 / Arduino 風格）⚠

```cpp
// micro-ROS 韌體骨架：訂閱 /<name>/request（UInt32MultiArray），處理後發布到 /<name>/response
#include <micro_ros_arduino.h>          // PlatformIO 用 <micro_ros_platformio.h>
#include <rcl/rcl.h>
#include <rcl/error_handling.h>
#include <rclc/rclc.h>
#include <rclc/executor.h>
#include <std_msgs/msg/u_int32_multi_array.h>

#define RCCHECK(fn)     { rcl_ret_t rc = fn; if (rc != RCL_RET_OK) error_loop(); }
#define RCSOFTCHECK(fn) { rcl_ret_t rc = fn; (void)rc; }

rcl_allocator_t allocator;
rclc_support_t support;
rcl_node_t node;
rcl_subscription_t sub;
rcl_publisher_t pub;
rclc_executor_t executor;

std_msgs__msg__UInt32MultiArray req, resp;
static uint32_t req_buf[64], resp_buf[64];       // ★ micro-ROS 沒有動態配置：序列欄位要自己給緩衝區

void error_loop() { while (1) { delay(100); } }

// 你的韌體邏輯：讀 req_buf[0..n-1]，寫 resp_buf，回傳寫了幾個 word（<0 = 不回）
int handle(const uint32_t *in, int n, uint32_t *out);

void on_request(const void *msgin) {
    const std_msgs__msg__UInt32MultiArray *m = (const std_msgs__msg__UInt32MultiArray *)msgin;
    int k = handle(m->data.data, (int)m->data.size, resp_buf);
    if (k < 0) return;
    resp.data.size = (size_t)k;
    RCSOFTCHECK(rcl_publish(&pub, &resp, NULL));
}

void setup() {
    set_microros_transports();                    // USB 序列埠；Wi-Fi：set_microros_wifi_transports("SSID", "PASS", "192.168.1.10", 8888);
    delay(2000);
    allocator = rcl_get_default_allocator();
    RCCHECK(rclc_support_init(&support, 0, NULL, &allocator));
    RCCHECK(rclc_node_init_default(&node, "board0", "", &support));
    RCCHECK(rclc_subscription_init_default(&sub, &node,
            ROSIDL_GET_MSG_TYPE_SUPPORT(std_msgs, msg, UInt32MultiArray), "board0/request"));
    RCCHECK(rclc_publisher_init_default(&pub, &node,
            ROSIDL_GET_MSG_TYPE_SUPPORT(std_msgs, msg, UInt32MultiArray), "board0/response"));

    req.data.data = req_buf;   req.data.capacity = 64;   req.data.size = 0;     // ★ 接收緩衝區
    resp.data.data = resp_buf; resp.data.capacity = 64;  resp.data.size = 0;    // ★ 發送緩衝區
    req.layout.dim.capacity = 0; resp.layout.dim.capacity = 0;
    req.layout.dim.size = 0;     resp.layout.dim.size = 0;

    RCCHECK(rclc_executor_init(&executor, &support.context, 1, &allocator));   // 1 = handle 數
    RCCHECK(rclc_executor_add_subscription(&executor, &sub, &req, &on_request, ON_NEW_DATA));
}

void loop() {
    RCSOFTCHECK(rclc_executor_spin_some(&executor, RCL_MS_TO_NS(10)));
}
```

**單一 Int32 版**：型別換成 `std_msgs__msg__Int32`、`ROSIDL_GET_MSG_TYPE_SUPPORT(std_msgs, msg, Int32)`、欄位 `msg.data`，不用緩衝區。

**RP2350 / Pico SDK 版（micro_ros_raspberrypi_pico_sdk）**的差異：`main()` 裡先 `rmw_uros_set_custom_transport(true, NULL, pico_serial_transport_open, pico_serial_transport_close, pico_serial_transport_write, pico_serial_transport_read);`，再用 `rmw_uros_ping_agent(1000, 120)` 等 agent，其餘 rclc 呼叫相同，`while (true) rclc_executor_spin_some(...)`。

**micro-ROS 常見坑**

| 坑 | 說明 |
|---|---|
| 序列欄位沒給緩衝區 | `*MultiArray`、`String` 收不到或當機。`.data.data` / `.capacity` 一定要設 |
| 訊息太大 | 預設傳輸的 MTU 只有幾百 bytes，單一訊息大約幾百 bytes 到 2 KB。大資料要**切塊**（每塊帶 job id + 偏移）或調整編譯設定 |
| executor handle 數 | `rclc_executor_init` 的數量要 ≥ subscription + timer + service 數 |
| 開機順序 | 先開 agent 再 reset 板子 |
| topic 名稱 | rclc 用相對名稱 `"board0/request"`，在 ROS 2 裡是 `/board0/request` |

### 2.3 不用 micro-ROS 的替代：序列埠橋接 node

如果考場沒提供 micro-ROS，可以讓板子用簡單的文字協定走序列埠，電腦上寫一個 ROS node 當橋：

```python
# file: serial_bridge.py   （需要 pyserial：pip install pyserial）
"""把 /board0/request 的數字陣列用一行文字送到板子，板子回一行文字，再發布到 /board0/response。
板子端協定：收到 "REQ 1 2 3\n"，回 "RESP 4 5\n"。"""
import threading

import rclpy
import serial
from rclpy.node import Node
from std_msgs.msg import UInt32MultiArray


class Bridge(Node):
    def __init__(self, name='board0', port='/dev/ttyUSB0', baud=115200):
        super().__init__(f'{name}_bridge')
        self.ser = serial.Serial(port, baud, timeout=0.1)
        self.lock = threading.Lock()                       # 寫序列埠與讀執行緒分開
        self.pub = self.create_publisher(UInt32MultiArray, f'/{name}/response', 100)
        self.create_subscription(UInt32MultiArray, f'/{name}/request', self.on_req, 100)
        threading.Thread(target=self.reader, daemon=True).start()

    def on_req(self, msg):
        line = 'REQ ' + ' '.join(str(v) for v in msg.data) + '\n'
        with self.lock:
            self.ser.write(line.encode())

    def reader(self):
        while rclpy.ok():
            line = self.ser.readline().decode(errors='replace').strip()
            if line.startswith('RESP'):
                out = UInt32MultiArray()
                out.data = [int(v) for v in line.split()[1:]]
                self.pub.publish(out)


def main():
    rclpy.init()
    node = Bridge()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.try_shutdown()


if __name__ == '__main__':
    main()
```

板子端（Arduino）：`Serial.readStringUntil('\n')` → 解析數字 → 計算 → `Serial.printf("RESP %lu %lu\n", a, b);`。

## 3. 題一：ROS 2 跑 eBNN 推論

### 3.1 題目大概長怎樣

- 給一個已訓練好的二值網路（權重、門檻打包好的陣列，或 eBNN 函式庫）與輸入資料（影像位元）。
- 要求：寫 / 補完推論函式，包成 ROS 2 node（電腦上或板子上），訂閱輸入 topic、發布預測。
- 評分：預測與參考答案一致；可能比效率。

### 3.2 推論怎麼算（記這個就夠）

```text
第一層（每個隱藏神經元 j）：
    matches_j = Σ_k popcount( ~(x[k] ^ W1[j][k]) )      ← XNOR + popcount
    h_j       = (matches_j >= T1[j]) ? 1 : 0            ← BatchNorm + sign 摺疊成門檻
    hidden 的 bit j = h_j

最後一層（每個類別 c）：
    score_c   = 2 * popcount( ~(hidden ^ W2[c]) & mask ) - n_hidden
    prediction = argmax(score)（同分規則照題目，通常取最小 index）
```

完整 C 實作：[A_演算法範例.md 的 `bnn_dense` / `bnn_argmax`](A_演算法範例.md#6-完整程式-algolabc)。

**常錯**：XOR 當成 XNOR；`>` 與 `>=`；位元放到 `31 - j`；打包順序（像素 (r, c) 在哪一位、哪個 word 是低位）；同分規則；`2p - n` 忘了乘 2；陣列迴圈 `<=` 越界。

### 3.3 做法 A：推論放在電腦的 Python node

```python
# file: ebnn_pc_node.py
"""訂閱 /camera/image（UInt64，8x8 影像），發布 /ebnn/prediction（Int32）。權重換成題目給的。"""
import rclpy
from rclpy.node import Node
from std_msgs.msg import Int32, UInt64

MASK64 = (1 << 64) - 1
W1 = [0] * 32                    # ← 題目給的 32 個 64-bit 權重
T1 = [32] * 32                   # ← 題目給的門檻
W2 = [0b111 << (3 * k) for k in range(10)]   # ← 題目給的最後一層權重


def popcount(v):
    return bin(v).count('1')


def infer(img):
    h = 0
    for j in range(32):
        if popcount(~(img ^ W1[j]) & MASK64) >= T1[j]:
            h |= 1 << j
    scores = [2 * popcount(~(h ^ W2[c]) & 0xFFFFFFFF) - 32 for c in range(10)]
    best = 0
    for c in range(1, 10):
        if scores[c] > scores[best]:          # 嚴格大於：同分取最小 index
            best = c
    return best, scores


class EbnnNode(Node):
    def __init__(self):
        super().__init__('ebnn')
        self.create_subscription(UInt64, '/camera/image', self.on_image, 10)
        self.pub = self.create_publisher(Int32, '/ebnn/prediction', 10)

    def on_image(self, msg):
        pred, _ = infer(msg.data)
        out = Int32()
        out.data = pred
        self.pub.publish(out)


def main():
    rclpy.init()
    node = EbnnNode()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.try_shutdown()


if __name__ == '__main__':
    main()
```

### 3.4 做法 B：推論放在板子上（micro-ROS）⚠

韌體用 2.2 的骨架，`handle()` 寫成：

```c
// request = [img_lo, img_hi]；response = [prediction, score0..score9]
#include "model.h"                      // 題目給的 W1[32][2]、T1[32]、W2[10]
static int popcount32(uint32_t x) { return __builtin_popcount(x); }   // Hazard3 / Xtensa 都有

int handle(const uint32_t *in, int n, uint32_t *out) {
    if (n != 2) return -1;
    uint32_t hidden = 0;
    for (int j = 0; j < 32; j++) {
        int m = popcount32(~(in[0] ^ W1[j][0])) + popcount32(~(in[1] ^ W1[j][1]));
        if (m >= T1[j]) hidden |= 1u << j;
    }
    int best = 0;
    int32_t s[10];
    for (int c = 0; c < 10; c++) {
        s[c] = 2 * popcount32(~(hidden ^ W2[c])) - 32;
        if (s[c] > s[best]) best = c;
    }
    out[0] = (uint32_t)best;
    for (int c = 0; c < 10; c++) out[1 + c] = (uint32_t)s[c];   // 負數以補數傳，電腦端再轉回 int32
    return 11;
}
```

測試（電腦）：

```bash
ros2 topic echo /board0/response
ros2 topic pub --once -w 1 /board0/request std_msgs/msg/UInt32MultiArray "{data: [1111638588, 1010976330]}"
```

### 3.5 我自己做的步驟

1. 讀題目：輸入格式（幾個 bit、怎麼打包）、權重格式、輸出 topic / 型別、同分規則。
2. **先在電腦用 C（或 Python）寫推論**，用題目給的測資比對到全對，再搬到板子。板子上除錯很慢。
3. 包成 node：subscriber callback 裡算、publish 結果。
4. `ros2 topic pub` 送一筆已知輸入，`ros2 topic echo` 看輸出，和電腦版比對。
5. commit：`Q1: 推論正確`；再優化（popcount 換 `__builtin_popcount` / `cpop` / PIO）。

### 3.6 今年可能的加料

- popcount 交給 **PIO**（見 [2-2 C7 範例 2、3](2-2_位元運算_RISC-V_PIO.md#c7-pio-範例程式)）：CPU 送 `x ^ w`，PIO 回相同位數。
- RISC-V：`xnor` + `cpop` 兩條指令算一個 word 的相同位數。
- 輸入資料由 PIO 從腳位讀進來（位元流），解析後再推論。

## 4. 題二：兩片板子平行推論

### 4.1 兩種切法

| | 模型平行（切神經元） | 資料平行（切影像） |
|---|---|---|
| 做法 | 每張影像的 32 個神經元：board0 算 0..a−1、board1 算 a..31，結果 OR 起來 | 影像 1 給 board0、影像 2 給 board1… |
| 好處 | **單張延遲低** | **吞吐量高**（每張只付一次通訊 / 固定成本） |
| 需要 | header 帶 first / count、合併 bits | 依序號重新排序 |

- **兩片速度不同時**：讓兩邊同時做完。設固定成本 c、board0 每單位 t0、board1 每單位 t1：`c + a·t0 = c + (32 − a)·t1` → `a = 32·t1 / (t0 + t1)`。
- **不要送一張等一張**：通訊延遲時板子是閒的，要 pipeline（先把下一張送出去）。
- **一定要序號**：多個請求在路上時，回應順序不保證。

### 4.2 協定（建議）

```text
request  = [header, img_lo, img_hi]        header = (seq << 16) | (first << 8) | count
response = [header（原樣送回）, bits]       bits = 神經元 first..first+count-1，放在原本位置（bit j = 神經元 j）
```

板子端 `handle()`：

```c
int handle(const uint32_t *req, int n, uint32_t *resp) {
    if (n != 3) return -1;                               // 先檢查長度，再讀 req[1]、req[2]
    uint32_t h = req[0];
    unsigned first = (h >> 8) & 0xFFu, count = h & 0xFFu;
    if (count == 0 || count > 32 || first + count > 32) return -1;
    uint32_t mask = (count == 32 ? 0xFFFFFFFFu : ((1u << count) - 1u)) << first;
    uint32_t hidden = 0;
    for (unsigned j = first; j < first + count; j++) {   // 只算自己負責的神經元
        int m = __builtin_popcount(~(req[1] ^ W1[j][0])) + __builtin_popcount(~(req[2] ^ W1[j][1]));
        if (m >= T1[j]) hidden |= 1u << j;
    }
    resp[0] = h;
    resp[1] = hidden & mask;
    return 2;
}
```

### 4.3 協調者（電腦，Python）✅

```python
# file: coordinator.py
"""把每張影像分給兩片板子（依速度切神經元），收齊後依序發布預測。
已用 v2 模擬考大題二的評分程式驗證（正確性與 pipeline）。"""
import rclpy
from rclpy.node import Node
from std_msgs.msg import Int32, UInt32MultiArray, UInt64

FULL = 0xFFFFFFFF
N_HIDDEN = 32
W2 = [0b111 << (3 * k) for k in range(10)]     # ← 換成題目的最後一層權重
SPLIT = 21                                     # board0 算 0..20、board1 算 21..31（依速度比例調）


def popcount(v):
    return bin(v).count('1')


def predict(hidden):
    scores = [2 * popcount(~(hidden ^ w) & FULL) - N_HIDDEN for w in W2]
    best = 0
    for c in range(1, len(scores)):
        if scores[c] > scores[best]:
            best = c
    return best


class Coordinator(Node):
    def __init__(self):
        super().__init__('coordinator')
        self.create_subscription(UInt64, '/camera/image', self.on_image, 100)
        self.req = [self.create_publisher(UInt32MultiArray, f'/board{i}/request', 100) for i in (0, 1)]
        for i in (0, 1):
            self.create_subscription(UInt32MultiArray, f'/board{i}/response', self.on_response, 100)
        self.pred_pub = self.create_publisher(Int32, '/ebnn/prediction', 100)
        self.next_seq = 0            # 下一張影像的序號
        self.next_out = 0            # 下一個該發布的序號
        self.missing = {}            # seq -> 還沒收到的神經元 mask
        self.hidden = {}             # seq -> 已收到的位元
        self.ready = {}              # seq -> 預測（等前面的先發布）

    def on_image(self, msg):
        img = msg.data
        seq = self.next_seq
        self.next_seq = (seq + 1) & 0xFFFF
        self.missing[seq], self.hidden[seq] = FULL, 0
        for board, first, count in ((0, 0, SPLIT), (1, SPLIT, N_HIDDEN - SPLIT)):
            m = UInt32MultiArray()
            m.data = [(seq << 16) | (first << 8) | count, img & FULL, (img >> 32) & FULL]
            self.req[board].publish(m)        # 不等回應，直接送下一張（pipeline）

    def on_response(self, msg):
        header, bits = msg.data[0], msg.data[1]
        seq, first, count = header >> 16, (header >> 8) & 0xFF, header & 0xFF
        if seq not in self.missing:
            return
        self.hidden[seq] |= bits
        self.missing[seq] &= ~((((1 << count) - 1) << first) & FULL) & FULL
        if self.missing[seq]:
            return
        del self.missing[seq]
        self.ready[seq] = predict(self.hidden.pop(seq))
        while self.next_out in self.ready:     # 依影像順序發布
            out = Int32()
            out.data = self.ready.pop(self.next_out)
            self.pred_pub.publish(out)
            self.next_out = (self.next_out + 1) & 0xFFFF


def main():
    rclpy.init()
    node = Coordinator()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.try_shutdown()


if __name__ == '__main__':
    main()
```

**再進一步（吞吐量更高）**：自己記每片板子「預計何時有空」，兩片都閒時切神經元（延遲最低），積壓時整張丟給最早能做完的那片（每張只付一次固定成本）。完整版見模擬考 `solutions/q2_parallel/coordinator.py`。

**健壯性加分項**：某片板子沒回應時逾時重送（`create_timer` 檢查每個 seq 的送出時間）；收到重複回應要忽略（`if seq not in self.missing: return`）。

```c
// 兩個核心各算一半的神經元；用 FIFO 傳結果（不用共享變數就不用鎖）
#include "pico/stdlib.h"
#include "pico/multicore.h"
#include "model.h"

static volatile uint32_t g_img[2];

static uint32_t layer1_range(const volatile uint32_t img[2], int first, int count) {
    uint32_t h = 0;
    for (int j = first; j < first + count; j++) {
        int m = __builtin_popcount(~(img[0] ^ W1[j][0])) + __builtin_popcount(~(img[1] ^ W1[j][1]));
        if (m >= T1[j]) h |= 1u << j;
    }
    return h;
}

static void core1_main(void) {
    while (true) {
        (void)multicore_fifo_pop_blocking();                     // 等 core0 說「開始」
        multicore_fifo_push_blocking(layer1_range(g_img, 16, 16));   // 算後半、回傳
    }
}

int main(void) {
    stdio_init_all();
    multicore_launch_core1(core1_main);
    // 每張影像：
    g_img[0] = 0x5262423Cu; g_img[1] = 0x3C42464Au;

    uint32_t h = layer1_range(g_img, 0, 16);                     // core0 算前半
    h |= multicore_fifo_pop_blocking();                          // 合併
    printf("hidden = 0x%08lx\n", (unsigned long)h);
}
```

## 5. 題三：三片板子跑排序 / SHA-0 / CRC32

### 5.1 架構

```text
/jobs/request ──> [dispatcher] ──┬─> board_sort ──┐
                                 ├─> board_sha0 ──┼─> [dispatcher] ──> /jobs/result
                                 └─> board_crc  ──┘
```

- 「三個要在三片不同的板子跑」：每片板子的韌體只實作一種演算法（同一份原始碼用 `#define ROLE` 編成三種也可以）。
- dispatcher **同時**把工作送給三片（平行），不要排序做完才送 SHA；也不要等上一個工作做完才送下一個（pipeline）。
- 結果依工作順序發布；用 job id 對帳。

### 5.2 協定（建議）

```text
request  = UInt8MultiArray：[job id 4 bytes little-endian] + payload
response = UInt8MultiArray：[job id 4 bytes little-endian] + 結果
   sort：payload 當 little-endian uint32 陣列，回傳排序後的陣列（或只回 min/median/max 以省頻寬）
   sha0：20 bytes 摘要
   crc ：4 bytes（little-endian）
```

> micro-ROS 單一訊息大小有限（見 2.2）。payload 大時要切塊：每塊帶 `job id、offset、總長度`，板子收齊再算；SHA 與 CRC 可以**邊收邊算**（CRC 用 `crc32_update` 分段、SHA 每滿 64 bytes 處理一個區塊），不需要存下整份資料。

### 5.3 板子端 `handle()`（依角色）⚠

```c
// 三片板子共用一份原始碼，用 -DROLE=0/1/2 編譯
// algorithms：見 A_演算法範例.md 的 radix_sort / sha / crc32_table
int handle_bytes(const uint8_t *in, size_t n, uint8_t *out, size_t *out_n) {
    if (n < 4) return -1;
    memcpy(out, in, 4);                                   // job id 原樣送回
    const uint8_t *p = in + 4;
    size_t len = n - 4;
#if ROLE == 0                                             // 排序
    size_t cnt = len / 4;
    uint32_t *a = (uint32_t *)(out + 4);
    memcpy(a, p, cnt * 4);                                // RP2350 / ESP32 都是 little-endian
    radix_sort(a, cnt);
    *out_n = 4 + cnt * 4;
#elif ROLE == 1                                           // SHA-0
    sha(p, len, out + 4, 0);
    *out_n = 4 + 20;
#else                                                     // CRC-32
    uint32_t c = crc32_table(p, len);
    out[4] = (uint8_t)c; out[5] = (uint8_t)(c >> 8); out[6] = (uint8_t)(c >> 16); out[7] = (uint8_t)(c >> 24);
    *out_n = 4 + 4;
#endif
    return 0;
}
```

### 5.4 dispatcher（電腦，Python）✅

```python
# file: dispatcher.py
"""每個工作同時送給三片板子，收齊後依到達順序發布一行摘要。已用 v2 模擬考大題三的評分程式驗證。"""
import struct

import rclpy
from rclpy.node import Node
from std_msgs.msg import String, UInt8MultiArray

KINDS = ('sort', 'sha0', 'crc')


class Dispatcher(Node):
    def __init__(self):
        super().__init__('dispatcher')
        self.create_subscription(UInt8MultiArray, '/jobs/request', self.on_job, 100)
        self.req = {k: self.create_publisher(UInt8MultiArray, f'/board_{k}/request', 100) for k in KINDS}
        for k in KINDS:
            self.create_subscription(UInt8MultiArray, f'/board_{k}/response',
                                     lambda msg, k=k: self.on_response(k, msg), 100)   # k=k！
        self.result_pub = self.create_publisher(String, '/jobs/result', 100)
        self.order = []          # 工作到達順序（job id）
        self.partial = {}        # job id -> {kind: 結果 bytes}

    def on_job(self, msg):
        data = bytes(msg.data)
        job_id = struct.unpack('<I', data[:4])[0]          # little-endian
        self.order.append(job_id)
        self.partial[job_id] = {}
        for k in KINDS:                                     # 三片同時開工
            req = UInt8MultiArray()
            req.data = list(data)
            self.req[k].publish(req)

    def on_response(self, kind, msg):
        data = bytes(msg.data)
        job_id = struct.unpack('<I', data[:4])[0]
        if job_id in self.partial:
            self.partial[job_id][kind] = data[4:]
        while self.order and len(self.partial[self.order[0]]) == len(KINDS):
            job_id = self.order.pop(0)
            r = self.partial.pop(job_id)
            n = len(r['sort']) // 4
            values = struct.unpack(f'<{n}I', r['sort'])
            crc = struct.unpack('<I', r['crc'])[0]
            out = String()
            out.data = (f'id={job_id} min={values[0]} median={values[n // 2]} max={values[-1]} '
                        f'crc32={crc:08x} sha0={r["sha0"].hex()}')        # 8 位小寫補零
            self.result_pub.publish(out)


def main():
    rclpy.init()
    node = Dispatcher()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.try_shutdown()


if __name__ == '__main__':
    main()
```

### 6.1 RP2350 硬體重點

- 雙核心：Arm Cortex-M33 ×2 或 Hazard3 RISC-V ×2，150 MHz；520 kB SRAM（10 個 bank）。
- 3 個 PIO × 4 SM；16 個 DMA 通道、4 個 DMA IRQ；32 個 SIO 硬體 spinlock、兩個核心間 FIFO（各 4 word）。
- 硬體 SHA-256、TRNG。

### 6.2 SHA-256 硬體加速器

**SDK（`pico/sha256.h`，連結 `pico_sha256`）**⚠

```c
#include "pico/sha256.h"

void sha256_hw(const uint8_t *msg, size_t len, uint8_t out[32]) {
    pico_sha256_state_t st;
    if (pico_sha256_start_blocking(&st, SHA256_BIG_ENDIAN, true) != PICO_OK) return;  // true = 用 DMA 送資料
    pico_sha256_update_blocking(&st, msg, len);      // 可多次呼叫
    sha256_result_t r;
    pico_sha256_finish(&st, &r);                      // 完成並釋放硬體
    memcpy(out, r.bytes, 32);
}
// 驗證：SHA-256("abc") = ba7816bf 8f01cfea 414140de 5dae2223 b00361a3 96177a9c b410ff61 f20015ad
```

**直接操作暫存器（datasheet 步驟）**：

1. 寫 1 到 `CSR.START` 初始化。
2. 把訊息寫進 `WDATA`，每次寫之前輪詢 `CSR.WDATA_RDY`。
3. 自己補填充（`1` 位元、0、64 位元長度；同 SHA-0 的規則）寫進 `WDATA`。
4. 輪詢 `CSR.SUM_VLD` 等最後一塊算完。
5. 從 `SUM0`..`SUM7` 讀 256 位元結果。

細節：每 512 位元一塊（16 次 32 位寫入）；每塊還要 57 週期處理，期間 `WDATA_RDY` 為低；最快約每 121 週期一塊（150 MHz 約 79 MB/s，用 DMA 32 位傳輸時）。SHA-256 定義為 big-endian word，`CSR.BSWAP`（**預設開**）會把小端資料轉過來。

## 7. 考場 SOP：自己動手的順序

**開場 10 分鐘**

1. `git clone` 自己的 repository，讀 README、每題的說明與評分方式（commit 題號格式！）。
2. 確認環境：`ros2 node list`、板子插上後 `ls /dev/ttyUSB* /dev/ttyACM*`、agent 能跑。
3. 看哪題有範本可直接填、哪題最便宜，排順序。

**每一題**

1. 讀規格：輸入 / 輸出 topic、型別、格式、位元組順序、同分規則、邊界。
2. **核心演算法先在電腦上寫、對測試向量**（C 用 `gcc -Wall -Wextra -fsanitize=address,undefined`）。
3. 搬到板子 / 包成 node。
4. 用 CLI 單點測：`ros2 topic pub --once -w 1 ...` + `ros2 topic echo ...`。
5. 正確了就 commit（`Q1: ...`），看 CI 分數。
6. 再做平行 / pipeline / 效率，每進一步 commit 一次。

**卡住時**

- 收不到東西 → [2-1 的除錯流程](2-1_ROS2.md#8-除錯流程與判讀表)（node → topic → 名稱型別 → 數量 → echo）。
- 數字不對 → 期望 vs 實際寫成二進位比；檢查 XNOR / 門檻 / 位元位置 / 位元組順序。
- 當掉 → 陣列越界、`n - 1` 在 `n = 0`、緩衝區沒給（micro-ROS 序列欄位）。
- 同一個錯卡 15 分鐘 → 先做別題。

**最後 15 分鐘**：不要大改；確認每題最後一次 commit 的 CI 分數就是你要交的版本。
